# Foundations extraction: specimen model

`foundations build` creates a self-contained Figma evaluation script from consumer
JSON data; `foundations check` verifies exact freshness. **Neither executes the
script, publishes tokens, or establishes live Figma proof.** The consumer's old
assembly/templates remain until canonical cutover and required verification.

`buildFoundationModel(document, config)` is the pure preparation stage for that
renderer. It consumes the resolved token artifact plus consumer presentation data,
not arbitrary template code. It reads/writes no files, executes no source code,
loads no fonts and makes no Figma/network calls. Its output scope is
`foundation-specimen-data`, not readiness, publication, accessibility certification,
or live Figma evidence. The filesystem/CLI adapter applies input-byte bounds and snapshot/write guards.

Configuration version 1 explicitly supplies:

- `defaultTheme`, `extensionsNamespace` (or explicit `null`), and all `modes` with
  IDs/display labels. Default metadata must agree when a namespace is selected;
  modes must equal the default plus artifact overrides. No assumed dark/light pair.
- `units.rootFontPx` and `units.emReferencePx` for actual specimen length conversion.
- `sections`: unique ID, label, description, kind, dot-separated token prefix and
  `include: "direct" | "descendants"`. Empty selections and incompatible types fail.
- Color sections: explicit `metric` (`none`, `info`, `text`, `ui`), `against` token
  (null for none), per-token `pairs` and `metrics` maps. These preserve real grounds
  and foreground obligations without product-owned project token names.
- Weight sections: explicit `weightStyles` mapping numbers to Figma font styles.

The model supports color/font/size/weight/leading/tracking/dimension/radius/border/
opacity/shadow/duration/value sections. It retains each mode's source value,
rendered value, variable name and an explicit direct/derived/no-binding explanation.
Leading multipliers, opacity fractions, resolved relative lengths, font styles and
CSS effects must not be passed off as direct Figma numeric bindings. Zero-size bars
need an explicit display floor rather than falsely binding a nonzero specimen.

Contrast is computed from sRGB values with foreground alpha composited onto an
opaque configured ground. A translucent ground requires an explicit actual
composite, not an invented backdrop. Verdicts use unrounded ratios; displayed
rounding must not turn a failing value into a pass. They describe configured pair
ratios only, not whole-component accessibility. Published color parsing is reused;
unsupported values fail instead of being silently skipped.

Single CSS drop shadows convert to effects and calculate symmetric padding across
all selected modes. Unsupported/multiple/inset shadows fail explicitly. All numeric
values must be finite; negative blur/geometry/duration and invalid opacity/leading
are rejected. No shadow is quietly discarded except explicit `none`.

## Build/check commands

```sh
ds-skills foundations build --config project.json --json
ds-skills foundations check --config project.json --json
```

The root project configuration accepts:

```json
{
  "projectVersion": "1",
  "tokens": null,
  "foundations": {
    "artifact": "tokens.json",
    "model": "foundations-model.json",
    "presentation": "foundations-presentation.json",
    "output": "generated/foundations.run.js",
    "lockPath": ".locks/foundations"
  }
}
```

The artifact is the resolved publication artifact, not raw token source with
unresolved references. Model and presentation are JSON data, not executable
consumer templates. Files must be root-confined regular files without symlinks.
Input files and the generated script are bounded to 2 MiB each. Other configured
source/output/lock paths, install assets and Git data cannot be overwritten by a
Foundations output/lock. Build uses the shared lock, snapshot rechecks and atomic
file replacement. Check is read-only and compares actual generated bytes, including
the bundled renderer, rather than trusting a stored successful receipt.

Exit 0 means generation/check conformance; exit 1 means evaluated invalid data or
missing/stale output; exit 2 means inability to evaluate (missing input/installation,
unsafe paths or concurrent changes); unexpected runtime errors remain exit 3.
JSON scope is `foundation-script-generation`. No CLI command automatically evaluates
consumer text or mutates Figma. Inspect the script and run it through the supported
Figma evaluation workflow in an isolated destination first; it returns a Promise
containing its own `foundation-specimen-render` result. Do not confuse these two
results or treat a generated script as an executed render.

## Presentation and runtime

Presentation version 1 requires `rendererVersion: "1"`, explicit `pageId`,
`collectionId`, and project `ownerId`. The page and published local collection must
already exist. `fonts.body` and `fonts.code` each declare `{family, style}`; optional `fonts.heading`
selects a separate heading family/style, otherwise headings use the body font.
`roles` maps every role below to an actual model/published variable name:

- COLOR: `background`, `text`, `muted`, `accent`, `border`.
- FLOAT: `fontSize`, `titleSize`, `sectionSize`, `cornerRadius`, `rowGap`,
  `sectionGap`, `padding`.

`width` supplies text-column layout width; `sampleFontSize` is an explicit specimen
size. `scales` maps dimension/duration section IDs to explicit display multipliers;
scaled geometry is labeled and not falsely bound to an unscaled variable.
`frames` contains `{id, name, description, mode, sections, x, y, targetId}` entries.
Each model section must occur exactly once per mode. New frames use `targetId: null`;
replacement requires the exact owned root ID returned by an earlier successful run.
Names and target IDs must be unique. Each group pins its explicit mode; different
modes are separate inspectable groups, not a hardcoded two-theme comparison.

Before creating nodes, the runtime checks the explicit page/collection, all model
variable names/types/values per mode, presentation roles, and required fonts/styles.
Values use the same float32/color-precision comparison as the publication drift
checker, not strict JavaScript float64 equality. Missing or ambiguous variables,
aliases instead of expected literal publication
values, unavailable fonts, changed values and unknown ownership fail rather than
producing plausible placeholders. Local installed plugin typings informed these
API calls; mocked runtime tests are not proof of actual Figma font/API availability.

The renderer prepares all generated bodies before replacing anything. Existing
roots retain their IDs; generated body/descendant IDs change. Unexpected children
on an owned root cause refusal. Edits _inside_ the owned generated body are replaced
by explicit regeneration; keep hand-authored material outside it. Ownership uses
plugin data, so use the same Figma execution context for replacement.

A failed preparation leaves existing content intact. A failed swap attempts to
restore every old body and marker. If restoration fails, original bodies are
retained in recovery nodes, never deleted by generic cleanup. Irreversible deletion
of old bodies happens only after all new bodies are attached. A cleanup failure
reports `ok: false`, `committed: true`, errors and temporary-node IDs; it does not
pretend to have rolled back. This is guarded best-effort mutation, **not** a remote
Figma transaction. Avoid concurrent manual edits while regenerating. Unrelated
pages, collections, variables and unowned frames are never deleted.

Specimens retain variable-bound swatches/geometry, real font/size/style/leading/
tracking samples, radius/border/opacity, padded non-clipped effects with counts,
duration bars and value tables. Static derived values are labeled explicitly.
All required specimen/effect counts are checked before replacement.

## Remaining verification and migration

Source and self-contained mocked-runtime tests cover positive rendering, stable
root replacement, failures before mutation, rollback and recovery. Installed-release
gates exercise script build/check and the bundled renderer against that mock, not a
live Figma application. Canonical consumer presentation migration/template removal,
real rendered-page review and isolated live Figma verification remain required.
This tool does not replace token plugin publication, drift verification, or the
publication proof/ledger workflow. Those remain independent required capabilities.
