# Reconcile drift without conflating evidence

Use the [project contract](../stack-orchestrator/references/project-contract.md).
Identify the exact scope/revision and requested claim first. Read the consumer's
blocking/advisory policy; do not impose one universal promotion ladder.

| Drift              | Compare and repair at the actual authority                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Recipe/token       | Intrinsic recipe shape/references and canonical tokens versus generated artifacts/runtime; no extra membership declaration                 |
| Component contract | Real APIs, specs, selected static source contracts and story references; source presence alone is insufficient                             |
| Story              | Applicable variants/states/actions/workflows/motion versus inventory and actual execution, preserving static/executed distinction          |
| Visual             | Current rendered states versus reviewed design and scope-bound review evidence; links or stale baselines do not prove agreement            |
| Publication        | Configured token artifact versus actual Figma drift and bound proof/ledger; ledger conformance is not a new live observation               |
| Host/runtime       | Intent contracts, permissions, cancellation, mocks and actual host behavior; a web test does not prove native execution                    |
| Tooling            | Actual packages/configuration versus declared framework/version/import policy                                                              |
| Library/curation   | Selected upstream/local provenance, ownership/deviations, accepted guidance and installed copies; unavailable sources are not removed APIs |

Use the corresponding installed checks rather than implementing local validators.
Inspect `curation check` and `curation installed check` separately from core asset
integrity. A refreshed source snapshot does not justify installing unreviewed prose
or overwriting copied-source components. Reconcile the deliberate local deviations.

For token drift, preserve source-to-Figma direction. Figma-side edits are proposals;
review the intended change in canonical source, regenerate and sync forward. Do not
bulk-import downstream values into canon or edit generated CSS to hide a mismatch.
The token publication ledger is not a per-component review journal. Update it only
for genuine publication-state changes with real bound proof.

Evaluate configured component evidence profiles with `components status evaluate`
and use `components promote --profile <profile> --consumer <consumer>` with the
actual project config for the requested claim. Static coverage, visual review and
publication remain independent evidence scopes. Missing, stale or failed required
evidence must remain visible; do not synthesize a pass from an unrelated dimension.

Return a short prioritized list: observed mismatch, authoritative files/evidence,
impact under the actual policy, smallest corrective action and exact verification.
Do not expand a local repair into an unrelated migration. Route component behavior
back through the component loop and assembly behavior through layout verification
when necessary. Preserve user edits and report unresolved gates honestly at handoff.
